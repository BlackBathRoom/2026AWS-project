# 章別AI生成小テスト：最終方針と引継ぎ

## ユーザーが指定した方向

選択した章の内容に沿って問題を提供する。問題だけでなく、出題形式もAIが作成・提案する。

## 接続方針

1. Cは選択章の承認・公開済み教材の版と出典範囲を特定する。
2. AIはその範囲を基に問題・形式・正解・採点基準・解説・概念タグ・出典を生成する。
3. 生成物を下書きとして保存し、教材承認者による確認を経て出題対象にする。既存の未承認教材/問題を公開しない方針を維持する。
4. Bは承認済み問題の中から対象章・理解度・復習予定に合う問題を選び、問題ID/版/形式を付けてAへ返す。
5. Aは形式に応じた入力UIを表示し、Bへ回答を送る。正解・採点基準は回答前のブラウザーに渡さない。
6. Bが回答を保存し、採点結果・解説・概念別進捗を返す。指導力の最終評価は人が行う。

AIに自由なHTMLや実行コードを作らせて画面に埋め込む方式にはしない。対応する形式の許可リストと検証済みデータ構造を用意し、未対応形式は再生成または確認待ちにする。

## 形式案（未確定）

単一選択、複数選択、○×、穴埋め、短文記述など。形式ごとの入力UIと採点契約が必要。現状の画面は単一選択のみで、これらが動作するという意味ではない。
記述問題でAIによる判定を採用する場合は、部分点・再判定・根拠・不確実時の扱いをB/Cで決める。

## 統合前に決めること

- 1回の問題数、難易度、形式の許可リスト。
- 教材登録時に生成するか、要求時に生成して承認待ちとするか。
- 承認者と承認単位、教材更新・撤回時の問題失効。
- 一問ずつ結果表示するか、終了後にまとめるか。
- 意味が同じ問題の重複防止。AIの生成ごとに新IDを付けて同じ概念の初回回答を水増ししない。

APIはまだ追加していない。形式を確定後、API_CONTRACT.md、types.d.ts、B/C実装、Aの入力画面を同時に更新する。
現在のモック問題は接続確認用であり、AIが生成した正式な章別問題ではない。
